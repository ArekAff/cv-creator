# Data formats

Everything is plain YAML/Markdown, so the person can read and edit it too. A complete,
consistent example lives in `examples/demo/` (a fictional person's folder). Copy its shapes.
`uv run cv validate` checks `profile/`; `uv run cv lint` checks a `cv.yaml`.

Dates everywhere: `2021`, `2021-03`, or `present`. IDs are stable; never renumber.

**One folder per person.** Several people can use one installation. Each has
`people/<id>/` containing `profile/`, `applications/` and `inbox/`, and the commands work on the
active person (`uv run cv profile current | use <id> | add "<Name>" | list`, or `--person <id or folder path>` for
a single command). In this file and in the skills, `profile/…` and `applications/…` always mean the
active person's folders. The `people/` folder itself can live outside the project: `people_dir` in
`cv.local.yaml` (or the `CV_PEOPLE_DIR` variable) sets it, e.g. to keep personal data out of
OneDrive. `uv run cv doctor` prints the exact path. Never write personal data anywhere else.

```
people/
  .active                      id of the active person (uv run cv profile use)
  <id>/                        one person (examples/demo/ has the same shape)
inbox/                         CV files waiting to be imported (uv run cv resume import)
profile/                       the knowledge base = the master resume + interview evidence
  profile.yaml                 identity, contact, spoken languages, preferences
  timeline.yaml                career scaffold: positions, education, certifications, projects, awards, publications
  trails/T001-<slug>.yaml      one strategic trail (story) each, from the sense-making interview
  skills.yaml                  skills inventory with evidence ids
  insights.yaml                cross-trail patterns, strengths, values, summary drafts
  sessions/<date>-<kind>.md    interview notes in the person's own words (append as you go)
  evidence/                    supporting files: reviews, emails, certificates
  imports/<date>-<name>/       one imported CV each (see "CV imports" below)
  master-resume.md             generated by `uv run cv master`
applications/
  tracker.yaml                 every listing: details, CVs sent, replies (uv run cv app ...; uv run cv tracker)
  <YYYY-MM-DD>_<company>_<role>/
    posting.md                 the job ad, verbatim, with source and date
    research.md                company research notes
    classification.yaml        technical | non-technical + family, seniority (listing-classifier; method/listing-classification.md)
    requirements.yaml          the ad broken down (job-analyst agent)
    coverage.yaml              requirement -> evidence matrix (evidence-mapper agent, updated after the gap interview)
    cv.yaml                    the tailored CV content (cv-writer agent)
    judging/round-N/           one folder per round of the write–judge loop:
      cv.yaml cv.pdf build.yaml    snapshot + build facts (uv run cv round save)
      changes.md                   what the cv-writer changed, finding by finding
      judge.yaml                   scores, verdict, findings (cv-judge; format in method/judge-rubric.md)
    notes.md                   layout choice, requested modifications, round verdicts, versions sent
    cv/                        generated LaTeX project (main.tex + support files + main.pdf)
    <Name>_CV_<Company>_<date>.pdf   the file to send
    sent/<date>/               the exact CV that went out: the PDF (+ cv.yaml) (uv run cv app sent)
```

## profile/profile.yaml
```yaml
schema_version: 1
person: {name, headline, location, email, phone, links: [{kind: linkedin|github|website|..., url}], photo}
languages: [{language: English, level: C1}]       # CEFR or native/fluent/basic
interests: []                                      # hobbies, if the person wants them on CVs
preferences: {target_roles: [], industries: [], locations: [], work_mode, cv_language, paper, photo_on_cv, avoid: [], notes}
```

## profile/timeline.yaml
IDs: positions `P01`, education `E01`, certifications `C01`, projects `PR01`, awards `AW01`,
publications `PUB01`. Get the next free one with `uv run cv next-id position` (etc.).
```yaml
positions:
  - id: P01
    type: employment            # employment | internship | freelance | volunteer | other
    title: Data Analyst
    organization: Lumina Retail
    org_context: "home & garden e-commerce, ~400 people"
    location: Kraków, Poland
    start: 2023-07
    end: present
    team: "analytics team of 5, reports to Head of Commercial Analytics"
    responsibilities:           # item by item, in their words, prioritised (Sagis step 1)
      - {text: "Demand forecasts for the buying team", priority: high, trails: [T002]}
    tools: [SQL, Python, Power BI]
    notes: ""
education:      [{id: E01, degree: MSc, field: ..., institution: ..., location: ..., start: ..., end: ..., thesis: ..., grade: ..., highlights: []}]
certifications: [{id: C01, name: ..., issuer: ..., date: 2023-05, status: completed | in-progress, url: ...}]
projects:       [{id: PR01, name: ..., role: ..., start: ..., end: ..., description: ..., tools: [], link: ..., trails: []}]
awards:         [{id: AW01, name: ..., issuer: ..., date: ..., description: ...}]
publications:   [{id: PUB01, title: ..., authors: ..., venue: ..., year: ..., link: ...}]
```

## profile/trails/T001-<slug>.yaml
Create with `uv run cv trail new "Their title for the story" --link P01`.
```yaml
id: T001
title: "Rebuilding the Monday regional report"   # their words
linked_to: [P02]                # positions / projects / education it belongs to
responsibility: "..."           # the high-value responsibility it exemplifies
why_chosen: "..."               # career interview reason, or "evidence for R03 of <application>"
timeframe: {start: 2022-09, end: 2023-01}
goal: "..."                     # the result they were working towards
status: outlined | partial | explored
context: "..."                  # situation at the start: organisation, stakes, constraints
actions:                        # Sagis step 2: one action per line
  - {id: A1, when: 2022-09, actor: self | other, action: "..."}
gaps:                           # Sagis step 3: probing cycle per gap (Fig. 3)
  - after: A1                   # the gap after this action
    situation: "..."            # incident, issue
    questions: "..."            # curiosities, concerns
    emotions: "..."             # feelings, impulses (never on a CV)
    wishes: "..."               # hopes, preferences
    intentions: "..."           # ideas, decisions
    quotes: ["their exact words worth keeping"]
outcomes:
  - {text: "...", metric: "6 h → 0.5 h per week", evidence: user_stated | documented, source: "evidence/…"}
competencies: [{name: stakeholder discovery, evidence: "what in this trail shows it (A2–A3)"}]
skills_used: [Power BI, SQL]
keywords: [their nouns, plus the standard terms recruiters search for]
accomplishments: ["CV-ready statement confirmed by the person"]
open_questions: ["..."]
sessions: [2026-10-30-career-interview-1]
```

## profile/skills.yaml
```yaml
skills:
  - {name: SQL, category: technical | tool | domain | methodology | soft | language,
     level: basic | intermediate | advanced | expert, years: 6, last_used: 2026,
     evidence: [T001, P01], aliases: [PostgreSQL, T-SQL], notes: ""}
```
Every skill needs `evidence`. `aliases` make `uv run cv search` find it under other names.

## profile/insights.yaml
```yaml
patterns: [{pattern: "...", seen_in: [T001, T003], cv_use: "summary"}]
strengths: ["..."]
values: ["..."]
working_style: "..."
career_direction: "..."
recurring_themes: ["..."]
summary_drafts: ["2–3 line profile in their voice"]
```

## profile/sessions/<date>-<kind>.md
Free Markdown: objective, language, depth, then the exchange in short form. Keep the person's
exact words for the important parts. Kinds: `career-interview-N`, `gap-interview-<company>`,
`debrief-<topic>`.

## applications/tracker.yaml (uv run cv app …, uv run cv tracker)
One entry per application folder. Change it with the commands or the tracker page: they check
dates, links and work modes, keep the key order and leave empty fields out. Hand edits are fine too.
```yaml
applications:
  - id: 2026-11-02_acme_data-analyst          # the folder name
    company: Acme
    role: Data Analyst
    status: interview     # draft | ready | sent | screening | interview | offer | accepted | rejected | no-response | withdrawn
    link: https://jobs.example.com/acme/123    # the listing
    source: LinkedIn                           # where the ad was found
    salary: 16 000–21 000 PLN gross/month      # as written in the ad; never estimated
    expected_salary: 19 000 PLN gross          # what the person asked for, if a form asked
    location: Kraków
    work_mode: hybrid                          # remote | hybrid | on-site
    deadline: '2026-11-20'
    contact: Anna Nowak (recruiter)
    created: '2026-11-02'
    sent: '2026-11-03'                         # first sent
    sent_via: company site
    next_step: second interview, Thu 10:00
    follow_up: '2026-11-14'                    # when to chase them or check; `cv status` says when it's reached
    notes: ""
    template: jakes                            # the latest build (uv run cv build)
    cv_pdf: Alex_Example_CV_Acme_2026-11-03.pdf
    headline: "..."
    sent_cvs:                                  # every CV that went out (uv run cv app sent), kept in sent/<date>/
      - {date: '2026-11-03', file: sent/2026-11-03/Alex_Example_CV_Acme_2026-11-03.pdf,
         cv_yaml: sent/2026-11-03/cv.yaml, template: jakes, headline: "...", via: company site}
    history:                                   # every status change, with what happened
      - {date: '2026-11-02', status: draft, note: created}
      - {date: '2026-11-03', status: sent, note: sent Alex_Example_CV_Acme_2026-11-03.pdf via company site}
      - {date: '2026-11-07', status: screening, note: call with Anna}
```
Whether they replied is derived, not stored: the first `screening`, `interview`, `offer`,
`accepted` or `rejected` in the history is the reply. `no-response` closes an application without
one. A CV sent without this tool is recorded with `uv run cv app sent <app> --file <cv.pdf>`.

## applications/<app>/requirements.yaml (job-analyst agent)
```yaml
job: {title, team, company, location, seniority, language, source, ats_likely: true|false,
      title_variants: [...]}
requirements:
  - {id: R01, type: must | nice, category: experience | skill | tool | education | certification | soft | domain | language,
     text: "as written in the ad", keywords: [exact posting terms], signal: "listed first; repeated 3x"}
keywords: [the ATS terms, spelled exactly as in the ad]
company_language: ["phrases from the ad/website worth mirroring when true"]
```

## applications/<app>/coverage.yaml (evidence-mapper agent, then the gap interview)
```yaml
- {req: R01, status: strong | partial | gap, evidence: [T001, P01], note: "...", ask: "neutral gap-interview opener"}
```

## applications/<app>/cv.yaml (you write it; template-agnostic)
```yaml
meta:
  template: jakes               # uv run cv templates; my:<name> for user layouts
  language: en                  # en | pl | de | ... (headings, dates, hyphenation)
  paper: a4                     # a4 | letter
  font_size: 11pt
  date_format: short            # short | long | numeric | year
  max_pages: 1
  sections_order: [summary, experience, projects, education, skills, certifications, languages]
  hide: []                      # sections present but not shown in this layout
  headings: {skills: Technical Skills}
  accent: ""                    # hex colour without '#', for layouts that use colour
  options: {}                   # layout-specific (see method/template-selection.md)
  target: {company: ..., role: ...}
header:
  name: ...
  headline: ...                 # title alignment (guide: line up your title)
  location: ...
  email: ...
  phone: ...
  links: [{kind: linkedin, url: https://..., label: optional display text}]
  photo: false                  # true = profile photo; or a file path
  quote: ""                     # ReCeiVe header quote, optional
summary: >-
  2–4 lines; **bold**, *italic* and [label](url) allowed in any text
experience:
  - title: ...
    organization: ...
    location: ...
    start: 2023-07
    end: present
    description: ""             # optional one-line context
    bullets:
      - {text: "...", source: [T002]}        # source = knowledge-base ids (required by lint)
volunteering: [same shape as experience]
projects: [{name, role, start, end, tech: [], link, description, bullets: [{text, source}]}]
education: [{degree, field, institution, location, start, end, thesis, grade, details: []}]
skills: [{category: Data, items: ["SQL (window functions)", Python]}]   # quote items that contain commas
        # items may also be {name: SQL, level: advanced} for layouts with skill bars/ratings
certifications: [{name, issuer, date, status: completed | in-progress}]
languages: [{language: English, level: C1}]
awards: [{name, issuer, date, description}]
publications: [{title, authors, venue, year, link}]
competencies: [{name: "Stakeholder discovery", text: "evidence in one line"}]
achievements: [{title: "6/6 regions", text: "...", icon: faTrophy}]   # icon = fontawesome5 command name
interests: ["...", "..."]
references: "Available on request."
custom: [{title: "...", text: "...", items: ["..."]}]
gdpr_clause: true               # true = standard RODO/GDPR consent text in the CV language; or your own text
```
YAML pitfall: in `[a, b (c, d)]` the comma inside the parentheses splits the item. Quote such
items: `["b (c, d)"]`. The lint reports unbalanced parentheses.

## CV imports (profile/imports/<date>-<name>/)
An existing CV the person brought (skill `import-resume`). `uv run cv resume import <file>` creates
the folder; the person's `inbox/` is imported when no file is given.
```
original.pdf | original.docx | original.md | original.png | original/<main>.tex (+ \input files, .cls/.sty, images)
text.md          extracted text (PDF/DOCX/LaTeX), or your transcription for images and scans
import.yaml      id, imported, source_name, original, kind, text_chars, text_quality, notes, resolutions
extracted.yaml   what the CV says, structured (you write it; format below)
diff.yaml        written by `uv run cv resume diff`: every item known / new / changed / partly-known
```

`extracted.yaml`: copy the CV **verbatim**. No improving, translating or merging.
```yaml
source: {file: original.pdf, language: en, dated: 2023-02}   # dated: when the CV was written, if known
person: {name, headline, location, email, phone, links: [linkedin.com/in/..., github.com/...]}
summary: "..."
positions:
  - {title, organization, type: employment | internship | freelance | volunteer | other, location,
     start: 2022-04, end: present, bullets: ["verbatim bullet", "..."]}
education:      [{degree, field, institution, location, start, end, grade, thesis, bullets: []}]
certifications: [{name, issuer, date, status: completed | in-progress}]
projects:       [{name, role, start, end, description, tools: [], link, bullets: []}]
awards:         [{name, issuer, date, description}]
publications:   [{title, authors, venue, year}]
skills:         [SQL, Power BI, ...]          # one name per item
languages:      [{language: German, level: B1}]
interests:      ["..."]
other:          ["anything that fits nowhere else, verbatim"]
```

How the diff decides (`uv run cv resume diff`):
- Entries are matched to the knowledge base by name similarity (organisation, title, school,
  certificate) and, for roles, overlapping dates. No match means **new**. A match with different
  dates, title or status means **changed**.
- Every bullet is a **claim**. It is *known* when one role or story in the knowledge base covers most
  of its words and every number in it. Otherwise it's *partly-known* or *new*, with the closest id
  given as a hint.
- Skills are matched against skill names, aliases, `skills_used`, tools and certificates. Languages
  are matched by name and level, interests against `profile.yaml interests`.
- Open items (anything not known and not resolved) are the interview agenda. `resolutions` in
  `import.yaml` (`uv run cv resume resolve <import> <key> --as covered|dismissed [--ref ID]
  [--note …]`) close items that were dismissed, or captured in words the diff can't see.
- `uv run cv status` lists CVs still in the inbox and imports with open items.
